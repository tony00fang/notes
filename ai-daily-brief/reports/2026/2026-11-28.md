## 重点动态

### 1. Copilot CLI 修复 MCP 与内置工具之间的授权串用

**领域：Coding｜24 小时内｜值得开发者立即升级验证**

**事实：**GitHub 于 11 月 27 日 13:04 UTC 发布稳定版 1.0.117。官方说明指出：当 MCP 服务器名称与内置权限类型相同时，批准该服务器在当前会话或位置使用工具，不再同时批准 Copilot 的内置 shell 命令、memory 存储等请求；恢复会话后仍保持服务器工具的授权。新版还修复自定义子 Agent 未正确遵循工具列表，以及可写 Git worktree 中现有仓库设置文件的只读保护问题。[官方 release notes，11 月 27 日](https://github.com/github/copilot-cli/releases/tag/v1.0.117)

**影响与判断：**这是一组有实质意义的权限修复，影响使用 MCP、子 Agent 与工作树隔离的团队。同名服务不应获得另一类能力，主 Agent 的限制也不能在委派后失效。发布说明确认修复内容，但没有提供受攻击案例或独立安全复测，因此不能写成已经发生大规模入侵。

**建议行动：**升级后用无敏感数据的测试仓库验证：批准 MCP 工具后，内置 shell 仍要求自身授权；恢复会话不会扩大许可；子 Agent 的实际工具集合与配置一致；仓库配置不能被普通执行步骤改写。保存版本、授权选择与调用日志，尤其检查长期会话。不要仅以一次正常代码生成成功，判断权限修复已经在自己的部署中生效。

## 今日推荐

- **阅读 TrojanPony 原始调查。**【7 天持续影响；11 月 26 日披露】AIR 报告称，伪装成“改进版”的 Coding Agent skills 携带 Windows 恶意载荷，统计到 487 个公开仓库；活动可追溯至 7 月，原始正版项目未被指感染。**这是安全公司研究，尚无独立核验；仓库数不是感染人数。**报告的价值在于提醒团队检查安装脚本和捆绑二进制，而非只看名称、星数或扫描 PASS。Windows 团队可先对照报告核查已安装来源及文件清单，避免运行可疑样本。[AIR 原文](https://www.air.security/blog-posts/trojanpony)
